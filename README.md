# AI Job Application Agent

A local Streamlit application that accepts only a job description, a resume PDF, its LaTeX source, and the HR email address. It analyzes the role, generates a tailored LaTeX document body in the existing template, compiles a PDF, drafts an email explaining the applicant's fit, and sends it from the authorized `officialshivam2419@gmail.com` account after one explicit Send confirmation.

## Features

- PDF and LaTeX upload validation, PDF text extraction, and a source similarity warning.
- Structured job analysis and resume tailoring using the Groq API.
- AI rewrites the LaTeX document body in the original template; the original preamble, macros, and trailer are preserved byte-for-byte, and existing URLs must remain unchanged. The original upload is never modified.
- `pdflatex` compilation without shell escape and readable-PDF checks.
- Final sender, recipient, email, and PDF review, followed by an explicit Gmail send.
- SQLite application history and per-application download links.
- Tests mock all LLM and email sending; no credentials are needed to run tests.

The AI-generated body is not automatically fact-checked. Review the tailored PDF for accuracy before sending; the app preserves the original LaTeX preamble and checks that URLs are unchanged.

## Architecture

- `app.py`, `ui/`: Streamlit screens and workflow state.
- `models/`: Pydantic domain and API-response validation.
- `services/`: PDF, AI, LaTeX, email, Gmail, and application persistence logic.
- `database/`: reserved for future persistence separation; SQLite access currently lives in `services/application_service.py`.
- `config/`, `utils/`: environment configuration, file/path controls, and logging setup.
- `tests/`: deterministic unit tests; no real API calls.

## Prerequisites

- Python 3.11 or newer.
- A Groq API key to use job/resume/email analysis.
- MiKTeX or TeX Live with `pdflatex` available on `PATH` to compile the tailored resume.
- Google Cloud OAuth client credentials and Gmail API enabled to send email.

## Configure Groq

Edit `.env` and set:

```dotenv
GROQ_API_KEY=your-key
GROQ_MODEL=openai/gpt-oss-120b
GMAIL_EXPECTED_SENDER=officialshivam2419@gmail.com
```

The app uses Groq's OpenAI-compatible API endpoint and the configured model. Resume and job content is sent to Groq for analysis; do not use this app with material you are not permitted to share with that service.

## Install a LaTeX compiler on Windows

Install [MiKTeX](https://miktex.org/download) or TeX Live and ensure its binary directory is on `PATH`. For MiKTeX, enable automatic installation of missing packages in the MiKTeX Console if desired. Restart the terminal/VS Code after changing `PATH`. The app reports a clear error if it cannot find `pdflatex`.

Compilation runs as a subprocess with an argument list, a timeout, and `-no-shell-escape`. It does not enable shell commands from LaTeX. This is not a full OS sandbox: compilation can still read local files accessible to the current user, so compile only source files you trust. The app never executes commands generated by the LLM.

## Configure Gmail OAuth

1. Create a Google Cloud project and enable the **Gmail API**.
2. Configure the OAuth consent screen. If the app remains in Testing mode, add the Google account that will authorize it as a test user.
3. Create an OAuth client ID for a **Desktop app** and download its client JSON.
4. Place the JSON in the project folder as `credentials.json`, or set `GMAIL_CREDENTIALS_FILE` in `.env` to its location.
5. On the first send, the app opens Google's user authorization flow in a browser. Authorize the account `officialshivam2419@gmail.com`. The app verifies this Google account before sending; an account mismatch prevents the send. The refresh token is saved to `token.json` (configurable with `GMAIL_TOKEN_FILE`). Keep both files private and out of source control.

The app requests Gmail's send scope plus OpenID/email identity scopes to verify the sender. It does not ask for or store a Gmail password. Email sending is never triggered by startup, upload, PDF generation, or reruns; it happens only after reviewing the recipient, message, and PDF and clicking **Send Email** once. Gmail API acceptance is not proof of delivery or that the recipient read the email.

## Configure local paths (optional)

`.env.example` documents all settings:

- `GROQ_API_KEY`, `GROQ_MODEL`
- `GMAIL_CREDENTIALS_FILE`, `GMAIL_TOKEN_FILE`, `GMAIL_EXPECTED_SENDER`
- `DATABASE_PATH`, `OUTPUT_DIR`, `LOG_LEVEL`

Relative paths resolve inside the project directory. `.env`, OAuth credentials/tokens, the local SQLite database, logs, and generated output are excluded from version control.
Streamlit is configured to bind to `127.0.0.1` so the app is local to the machine by default.

## Run the application

```powershell
.\.venv\Scripts\streamlit.exe run app.py
```

Or, with the environment activated:

```powershell
streamlit run app.py
```

Workflow: enter the job description and HR email, upload the PDF and matching `.tex`, review the analysis and generated LaTeX source, confirm review, compile and inspect the tailored PDF, review the generated message, then click **Send Email** to transmit it. Job title and company are extracted from the job description when stated; applicant identity comes from the resume.

## Troubleshooting

- **Missing Groq API key:** add `GROQ_API_KEY` to `.env` and restart Streamlit.
- **Invalid AI response or LaTeX compilation failure:** retry the analysis, then inspect the generated `.tex` source and compiler setup. The original preamble and trailer remain unchanged.
- **PDF/source mismatch:** verify the PDF and `.tex` are versions of the same resume.
- **`pdflatex` not found:** install MiKTeX/TeX Live, add `pdflatex` to `PATH`, and restart the application.
- **Compilation errors:** check that required TeX packages are installed and that the source compiles independently. The app does not rewrite the template to hide compiler errors.
- **Gmail authorization error or sender mismatch:** verify Gmail API enablement, OAuth Desktop credentials, consent-screen test-user access, and the configured client JSON path. Authorize `officialshivam2419@gmail.com`. If a previous token lacks the identity scopes, the app asks to authorize again. Remove the local token and reauthorize if access was revoked.
- **Gmail rate limit:** wait before retrying. After a failed send attempt, the exact reviewed message must be confirmed again to guard against duplicate sends after an ambiguous network failure.

## Privacy and known limitations

- Uploaded documents and generated artifacts are processed locally, except resume/job text sent to Groq for requested AI features.
- The SQLite history records company/job/recipient, filenames, status, subject, timestamp, and Gmail message ID; it does not store OAuth secrets or resume text.
- Generated files are retained in `output/<application-id>/` until manually removed.
- Similarity comparison is a token-overlap warning, not document identity proof.
- The AI is instructed not to invent resume facts, but generated content is not automatically fact-checked; the user remains responsible for reviewing every claim.
- Layout overflow is not automatically detected. Inspect the PDF before sending it.
- Gmail API success means the API accepted the message; it does not establish inbox delivery, receipt, or readership.
